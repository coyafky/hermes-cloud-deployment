# Hermes Sales Agent — 内部销售助手说明

## 它是谁？

Hermes Sales Agent 是基于 **Hermes Agent 框架**构建的一个**飞书（Feishu）AI 机器人**，目前服务于 **有膜有漾（You Mo You Yang）** 品牌的门店销售、招商人员和客服团队。

它在飞书中以机器人身份运行，团队成员在飞书群聊中 @它 或直接私聊即可获得即时支持。

## 整体架构

```
                  飞书客户端
         (销售在群里 @机器人 或私聊)
                     │
                     ▼
       ┌──── 飞书网关 (WebSocket) ────┐
       │  FEISHU_APP_ID / APP_SECRET   │
       │  权限: DM配对模式 + 提及触发   │
       └─────────────┬───────────────┘
                     │
                     ▼
        ┌──── Hermes Sales Agent ────┐
        │  LLM: DeepSeek V4 Flash     │
        │  上下文: 最长 90 轮对话      │
        │  联网搜索: Tavily            │
        └──────┬──────────┬─────────┘
               │          │
               ▼          ▼
       ┌──────────┐ ┌────────────┐
       │飞书操作   │ │ 销售技能库  │
       │(lark-cli) │ │(11模块系统) │
       └──────────┘ └────────────┘
```

Agent 通过 WebSocket 连接到飞书，拥有操作飞书各项资源的权限。核心飞书技能（25个）包括：

## 第二层：销售业务能力（11 模块体系）

这是 Agent 的**核心价值**——一个覆盖汽车膜销售全流程的模块化技能系统，共 12 个技能（1 个中枢 + 11 个业务模块）。

### 销售全流程导航

```
客户发来消息
     │
     ▼
┌─ 需求是否模糊？ ──→ 模块1: 获客咨询 (ask-with-mom-test)
│                         │
│                    发现真实需求
│                         │
└────────── ▼ ────────────┘
     │
     ▼
┌─ 模块2: 需求诊断 (diagnose-with-spin-selling)
│  SPIN 四步法：现状→问题→影响→需求回报
│
├─→ 客户问价格/风险/对比？
│      └─→ 模块3: 客户教育 (answer-customer-faq-transparently)
│
└─→ 模块4: 产品推荐 (recommend-film-product)
        │
        ├─→ 线上 → 异议？议价？接受？
        │       ├─ 异议 → 模块5: 异议处理 (handle-film-objections)
        │       ├─ 议价 → 模块6: 谈判推进 (negotiate-with-tactical-empathy)
        │       └─ 接受 → 模块8: 成交推进 (close-deal)
        │
        └─→ 到店 → 模块7: 到店接待 (in-store-service)
                          │
                     确认方案 → 模块8: 成交推进
                          │
                     施工完成 → 模块9: 售后关怀 (customer-success-followup)
                                        │
                                   模块11: 跟进消息 (write-sales-followup)
                                        │
                                   回到入口 → 新客户
```

### 每个模块解决什么问题

**模块 1 — 获客咨询** (`ask-with-mom-test`)
基于《The Mom Test》原则，帮助销售问出客户真实需求。专门处理客户说"想了解一下""随便看看"这类模糊信号。核心理念：问过去事实，不问未来假设；问具体细节，不问泛泛意见。

**模块 2 — 需求诊断** (`diagnose-with-spin-selling`)
基于 SPIN Selling 方法论的四步诊断：了解现状 → 发现问题 → 放大影响 → 引导客户自己说出需求价值。当客户的痛点存在但需求不明确时使用。

**模块 3 — 客户教育** (`answer-customer-faq-transparently`)
基于《They Ask, You Answer》原则，透明回答客户最关心的五大类问题：价格、风险、对比、评价、最佳选择。不回避敏感话题，用清晰的教育建立信任。

**模块 4 — 产品推荐** (`recommend-film-product`)
按 车型→预算→用车环境→主要诉求 的路线为客户匹配合适的产品（隐形车衣/窗膜/改色膜）。每次推荐给出 1 个主推 + 1 个升级备选，所有参数从产品知识库精确匹配。

**模块 5 — 异议处理** (`handle-film-objections`)
处理"太贵了""有没有必要""会不会伤车""质保多久"等标准异议。包含甲醛/苯健康异议、后喷漆风险告知、防眩光测试方法等专业内容。

**模块 6 — 谈判推进** (`negotiate-with-tactical-empathy`)
基于《Never Split the Difference》的战术同理心谈判法。处理价格抵触、犹豫、竞品比较、家庭决策延迟等场景。核心技巧：镜像（Mirror）→ 标注（Label）→ 校准问题 → 总结 → 低压下一步。

**模块 7 — 到店接待** (`in-store-service`)
客户到店后的完整接待流程。覆盖 5 种客户画像（新车车衣/旧车窗膜/改色/比价/路过），包含样膜引导、施工前 checklist 和到店报价模板。

**模块 8 — 成交推进** (`close-deal`)
客户说"好"之后的执行流程。三确认（方案/价格/意愿）→ 四大成交场景（爽快/犹豫/条件/线上）→ 定金引导 → 施工确认单。

**模块 9 — 售后关怀** (`customer-success-followup`)
从施工当天下到术后一年的客户生命周期管理：Day3 基础回访 → Week1 满意度确认 → Month1 效果回访 → Month3 转介绍引导 → Month6 维护提醒 → Year1 质保提醒。覆盖满意、有问题、沉默、投诉四大情景。

**模块 10 — 话术润色** (`strengthen-sales-wording-with-influence`)
基于《Influence》七大伦理影响力原则（互惠、喜好、社会认同、权威、稀缺、承诺一致、联盟）来润色销售话术。不操控、不造假、不编造稀缺。

**模块 11 — 跟进消息** (`write-sales-followup`)
生成 80-150 字的可复制微信/飞书跟进消息。覆盖推荐后跟进、报价后跟进、嫌贵后跟进、施工后提醒等场景。

## 第三层：产品知识库

Agent 内置了一个结构化产品知识库（JSONL 格式，约 24 条记录），涵盖：

- 3 条企业介绍（品牌、服务理念、工艺）
- 8 条隐形车衣产品（YM-60/65/70/80/80Y/10/100/1000 全系列）
- 7 条窗膜产品（春分/谷雨/小满/芒种/白露/网红/养生）
- 1 条改色膜入口
- 2 条售后养护 SOP
- 1 条价格政策脚本

每条记录包含：产品摘要、销售话术、技术参数（规格表）、边界声明（不能说什么）、来源页号。销售问具体参数时，Agent 会精确匹配产品 ID 并引用来源页，不会凭空编造数据。

## 第四层：行为准则（Always-Active SOUL）

以下规则即使在用户不主动调取任何技能时也始终生效：

- **角色定位**：有膜有漾内部销售助手，服务于门店销售、招商人员、客服
- **语言风格**：专业、简洁、自然。优先给出可直接复制的话术版本。情绪化客户先安抚再解释再给下一步。不夸张、不绝对、不攻击竞品
- **推荐流程**：车型 → 预算 → 用车环境 → 主要诉求。信息不足时先给初步方向并追问
- **信息边界**：不承诺服务手册之外的质保/价格/时效/活动/库存。不做责任判定，争议建议回店处理
- **售后核心**：贴膜后三天不跑高速（限速60），改色膜三天回店复检，不洗车；雷达问题回店处理；污染物及时清理

## 权限与安全

- 所有 Group 对话要求 **@提及** 才触发 Agent 响应
- 支持 **白名单模式**（固定用户列表）和 **DM 配对模式**（管理员审批）
- lark-cli 命令区分 `--as bot`（只能访问机器人权限内的资源）和 `--as user`（需要用户授权）
- 所有写操作（创建/修改/删除）要求先预览、再确认、后执行
